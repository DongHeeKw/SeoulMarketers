# 24. Owner actions & learning-first kick-off

## 사용자에게 기술 리뷰 요구 금지
사용자는 도시가 매력적이고 조작 가능한지, 어떤 창업 질문이 실제로 가치있는지만 피드백한다. Agent가 카메라 좌표, SQL, 타입, 테스트, WebGL 메모리 관리 책임을 진다.

## 화면 및 행동 계약
SM-U01: 진입 3D 미니어처 도시 — '도시를 탐험' CTA. 초기 장면은 DEMO이며 실제 상권과 혼동 금지.
SM-U02: 지역 선택 → 선택 지역 명칭·업소 수·데이터 날짜 정보 패널.
SM-U03: 업종 버튼 → 화면 아이콘과 집계가 동시 변경.
SM-U04: 지역 A/B 비교 → 동일 기준·기간·단위의 업종 밀도 비교.
SM-U05: 업종 배치 타이쿤 시뮬레이터 → 매출/비용 *사용자가 지정한 가정*으로 손익 변화 시각화. 사실 예측 아님.
SM-U06: 사장님 리포트 → 주변 변화와 공개 정보. 사장님 개별 매출은 동의 없이 수집·공개 금지.
SM-U07: 저장된 시나리오와 유용한 월간 업데이트로 재방문. 사용 시간을 늘리는 것만을 위한 무한 게임 루프 금지.
SM-U08: 유료 SaaS 및 커뮤니티는 데이터 품질·사업자 요건·개인정보/신고 정책 준비 후 출시.

## TDD 첫 단계
1. Pure `getBusinessesWithinRegion()`에 대한 경계/중복/누락 테스트부터 작성.
2. Three.js 건물 선택: 동일 ID가 3D 선택·2D 대체 리스트·정보 패널에서 일치하는 E2E.
3. 3D 미지원 시 2D 검색도 동일 유용정보 제공.
4. 비용 시나리오: 명시된 매출·원가·임대·인건비에 따라 손익이 계산되고 입력 오류 차단.

## 사용자 학습 경로
`Canvas`의 카메라/scene부터 읽지 않고 `test` → `domain` → `UI component` → `scene` 순서. 차트·입력 폼의 결과를 수기로 계산하고 코드와 비교.

## 아직 없는 데이터
개별 상가 실매출, 신뢰 가능한 가게 폐업 확정 시점, 창업 성공확률, 임차료 전체 시장 시세. 공개 점포의 존재가 매출 증거는 아니다.
